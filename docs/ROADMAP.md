# Swob 产品路线图

> 最后更新：2026-03-25

## 产品定位

像整理云文档一样整理你的 Claude Code 聊天记录。核心用户：重度使用 Claude Code 的 vibe coder，尤其没有编程基础的用户。核心操作：找到历史会话 → 恢复对话。

理念：一个对话窗口有更长的生命，每次想起来都会恢复。

---

## 一、文件夹整理

### 问题：文件夹辨识度不够
- 支持文件夹 icon（可上传图片，也可选择 emoji）
- 文件夹 tag（自己的色彩）
- 文件夹高亮（用颜色）
- 文件夹置顶
- 文件夹右键菜单：置顶、显示文件夹 info、文件夹设置（智能归类规则）、改 icon、移动到

### 问题：文件夹内 session 多了就乱
- 支持文件夹内 session 拖拽排序（现在顺序自动不可调）
- 至少按更新时间从新到旧排序
- active 的 session 自动排到前面

---

## 二、聊天记录显示

### 问题：user 和 assistant 看着不契合 CC 也不契合用户
- 机器人头像改成 Claude Code 的小螃蟹
- user 和 assistant 的名字和头像，要能用户自定义修改（在设置里）

### 问题：中间视图太多太乱
- 精简模式和完整模式差别不大，去掉完整模式
- 展示 AI 友好的格式给用户，甚至可以不做人类友好的 markdown 视图

### 问题：部分样式不太完善
- 胶囊样式美化，不要带缩进
- 行间代码块样式美化，不能跟行内一样有文字单行底色
- 代码块支持一键复制按钮

---

## 三、导出分享和上下文传递

### 问题：导出内容无法自定义，全部导出太冗余
- 多选后导出为长图
- 仅导出用户 prompt，过滤掉 agent 回答
- 导出不含工具调用过程的版本

---

## 四、回顾与洞察

### 问题：右侧边栏信息冗余无重点
- 重新组织右侧边栏信息架构
- 显示：调用过的 skill/plugin、使用过的 slash command、生成的子 Agent、token 消耗统计、所用模型、effort 情况
- 工作目录：左键一键复制路径（不是打开），右键菜单：打开、定位、复制

### 时间追踪与工作回顾
- Tag 功能：session 和文件夹都可指定 tag，tag 有自己的主题色
- 根据 tag 自动绘制：每天工作时间轴、token 消耗、每周时间轴、每天热力图
- 示例：swob 文件夹 → 紫色，keykeeper → 黄色，nightguard → 深蓝色
- 支持导出分享，让 vibe coder 看到自己的工作量

---

## 五、Session 恢复、创建与切换

### 问题：创建新 session 太麻烦
- 快捷创建 session：通过全局快捷键，对话式指定目录、指定标签，一步创建

### 创建分支对话
- 一键基于当前会话上下文创建分支对话
- 自动把当前会话 compact 结果输入给新对话
- 可设置传入内容：仅 compact 结果 / 完整聊天记录 + compact 结果
- 在 Swob 中显示为"共享上下文"的对话

### 问题：文件夹层级多了找不到要恢复的 session
- 全局快捷键快速切换窗口
- 类似 Spotlight 的全局模糊搜索框，不打开界面也能搜索和切换 session
- 用户可自定义录入快捷键

### 问题：resume 参数不够灵活
- 用户可自定义 resume 附带的参数标签
- skip-permission 是可删可加的标签
- 支持自定义标签如 `--worktree`

### 问题：状态感知滞后
- 优化 active 识别，实现与终端窗口打开/关闭完全同步（现在关窗口后绿点还在）
- 实时感知新 session（现在滞后，需重启才能刷出新对话）
- 当前 active 的会话，聊天记录应与终端实时同步

---

## 六、Agent 原生化

### 问题：session 多了手动整理很累，新用户更不可能手动整理
- 开放 CLI，让 AI 可以直接操作文件整理等
- 让整理 session 这件事可以直接让 Claude Code 做
- 整个 Swob 开放给 Claude Code：人能做的操作 CC 都要能做
- 包括：打 tag、划线高亮、导出 markdown 到指定位置、修改设置

---

## 七、定制化与个性化

### 问题：默认设置是开发者习惯，不一定是用户习惯
- 设置页面：主题、侧边栏显示功能、快捷键
- 浅色/暗色主题：跟随系统 or 固定，用户自己设置
- CLI 权限范围配置：
  - 手动模式：CLI 权限完全可控
  - 全量模式：可改设置
  - 完全模式：甚至可改源码自己迭代产品（实验性）
- 右侧边栏显示内容可配置
- 保存的 md 版本含不含工具调用可配置

---

## 八、UI 细节

- 像素风 Loading 动画（参考 Elys 风格）
- 所有按钮 hover 鼠标改为点击手形（cursor: pointer），目前是默认指针

---

## 九、云端同步

至少让用户知道聊天记录全存在 Document 文件夹，iCloud 可以同步。具体方案待定。

---

## 十、支持 OpenClaw

解析和管理 OpenClaw 聊天记录格式，扩展为通用的 AI 编程助手聊天记录管理器。

---

## 十一、用户反馈闭环

### 问题：和用户没有建立联系，无法矫正需求认知偏差
- Discord 社区（内置 bot 帮助回复和收集反馈）
- 联系开发者邮箱
- 应用内快捷反馈（直接输入内容发送给开发者）
- 内置 GitHub 链接（方便 star）

---

## 十二、落地页分发

### 问题：光靠 GitHub 无法直观传递产品理念
- GitHub 链接 + 下载按钮
- 动图演示 + 嵌入交互式 demo
- 使用场景：聊天记录恢复、文件夹式整理、拖拽作为上下文、快捷切换和恢复对话

---

## 执行策略

### 并行线路（最多同时 3 条）

**线路 A：UI 打磨**（样式层，低冲突）
cursor 修复 → 代码块美化 → 胶囊样式 → 螃蟹头像 → 像素风 Loading

**线路 B：侧边栏功能链**（都改 Sidebar，串行）
文件夹 icon/置顶 → 右键菜单 → Tag 系统 → session 排序 → 信息增强

**线路 C：中间区域功能链**（都改 ChatViewer，串行）
去掉完整模式 → 导出选项 → resume 参数标签 → 工作目录改进

### 后续阶段

**阶段 2**：设置页面 → 个性化 → 全局快捷键 → CLI 开放
**阶段 3**：时间追踪热力图 → OpenClaw → 分支对话 → 状态感知优化
**阶段 4**：落地页 + Discord + 云端同步方案

## 营销素材

**一句话定位：** 像整理云文档一样整理你的 CC 聊天记录

**核心卖点：**
- 恢复每一轮被 compact 之前的记录
- 支持全文/多选导出为 markdown
- 从侧边栏直接拖拽到别的会话作为模型上下文
- 划线笔记、云端同步、自动备份、分条导出
- 在 agent 之间传递聊天上下文
- 一键 resume 继续对话

**目标用户：** 重度 Claude Code 用户，尤其是没编程基础纯 vibe coding 的用户。不懂 cd 到项目目录，传统以 project 为主的工具不适用。并行多项目、多 session，需要统一整理。

**用户故事：** 我想继续开发 swob，就在侧边栏找到 swob 文件夹，点击想恢复的会话，点一下 resume 就行了。
